# agentboard v0.1.3 实现计划（完整范围：原始五项）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** 恢复并完成 Pitwall 功能映射批准的全部五项：① ZCode hooks 等待检测（Rust 校验桥）② 脱敏字段对齐（tool_summary/reply_head）③ 行内"在等什么"+完成摘要 ④ 设置页来源健康 ⑤ Needs Attention 消除。附带收益：Claude 获得即时权限等待与真实完成（Stop），为 v0.2 审批铺路。

**Architecture:** hooks 数据层先行（Task 1 Claude 扩展 / Task 2 ZCode 桥），消费与显示随后（Task 3 行内 UI），健康可见性（Task 4），交互（Task 5），打包（Task 6）。

**Tech Stack:** 不变 + sysinfo（进程链校验）。参考件：docs/reference/pitwall-collector/（MIT，schema 与校验逻辑权威来源）。

**Spec:** docs/superpowers/specs/2026-11-17-agentboard-design.md + docs/reference/pitwall-analysis.md。

## Global Constraints

- hook 铁律：observe-only 快速退出、任何异常 exit 0、无 stdout、无网络；ZCode PermissionRequest hook 由 ZCode 等待（timeoutMs 65000），桥必须毫秒级返回以免拖慢原生弹窗
- 推不出不硬标；通知不含请求内容；reason/tool_summary/reply_head 按 Pitwall 截断设计（120/160 字符，属"告诉用户在等什么"的验证过的例外）
- ZCode 配置修改前预检第三方 hooks（enabled=false 或损坏 → 拒装提示），备份到 ~/.agentboard/backups/，记录 hooks.enabled 原状（~/.agentboard/zcode-hooks-state.json）供卸载恢复；其余 hook 原样保留
- 每任务 fmt + cargo test --release + vitest 全绿 + commit；Task 6 版本 bump 0.1.3
- gh 需 `export HTTPS_PROXY=http://127.0.0.1:7897`；磁盘 os error 112 → 删 src-tauri/target/debug/{incremental,build}

### Task 2: ZCode hooks 桥——Windows 校验 + 注册器（①）

**Files:** Modify `src-tauri/src/hook_main.rs`、`src-tauri/src/events_file.rs`（zcode schema）、`src-tauri/src/installer.rs`、`src-tauri/src/collectors/claude_events.rs`（泛化改名 events_consumer 或加 zcode 消费）、`Cargo.toml`（sysinfo）；Create `src-tauri/src/zcode_hook.rs`

**Interfaces:**
- Produces:
  - `zcode_hook.rs`：`run_zcode_hook(event: &str, stdin_json: &str, now_ms: u64) -> Option<String>` 纯函数（可测）+ main 入口接线：①event ∈ {PreToolUse, PermissionRequest, PostToolUse, PostToolUseFailure} ②进程链校验：sysinfo 自 PPID 上溯 ≤8 层找 process name == "ZCode.exe" ③PermissionRequest 时 rusqlite readonly 查 `SELECT 1 FROM session WHERE id=:sid AND parent_id IS NULL AND task_type='interactive' AND time_deleted IS NULL`（db 路径 ~/.zcode/cli/db/db.sqlite；查不到→None）④产出事件行：`{v:1, ts:payload.timestamp ISO→epoch ms（解析失败→now）, agent:"zcode", event, session_id, turn_id(payload.turnId), tool_name, tool_use_id, tool_summary(PermissionRequest 时 tool_input.command/file_path/url/path 首行 120 字), payload_keys}`——**不记 message/reason/error**（Pitwall 对 zcode 刻意抑制）
  - hook_main.rs：`agentboard-hook.exe zcode <event>` 子命令（argv[1]=="zcode" 走 zcode 桥；无参走既有 Claude Notification 路径）
  - installer.rs：`install_zcode_hooks()` / `uninstall_zcode_hooks()`——配置 ~/.zcode/cli/config.json：预检（存在第三方 disabled/malformed hooks → 拒装返回错误提示）、备份、设 `hooks.enabled=true` + `hooks.events` 四事件各 ensure 一组 `{hooks:[{type:"process", command:<agentboard-hook.exe 路径>, args:["zcode","<事件名"]... }], timeoutMs:65000}`（结构照 Pitwall install.sh 267-275 行：nested events 形状）；原状记录 ~/.agentboard/zcode-hooks-state.json；卸载只删含我们命令的组 + 按 state 恢复 enabled；幂等。`ours_registered_zcode()` 健康检查用
  - events 消费：claude_events.rs 泛化为按 agent 文件消费（events/zcode.jsonl → AgentKind::ZCode：PermissionRequest→Waiting(Permission, reason=tool_summary)、PreToolUse/PostToolUse/PostToolUseFailure→Activity）
- [ ] Step 1: 失败测试（run_zcode_hook 纯函数：事件过滤/进程链 mock 注入/PermissionRequest 无 db 行→None/tool_summary 截断/schema 完整性；installer 临时目录 zcode 注册幂等/预检拒装/卸载恢复）
